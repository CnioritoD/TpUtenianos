Objetivo Una empresa de domótica quiere que los usuarios conﬁguren sus casas usando scripts sencillos en lugar de aplicaciones complejas. Para ello deberán diseñar y construir los analizadores léxico,  sintáctico y semántico que permita analizar, validar scripts que contienen reglas de automatización ejecutables por un controlador central (no implementado) además de generar una interfaz web que representa el estado y control  de una casa inteligente en tiempo real.  Este trabajo se enfoca en el Internet de las Cosas (IoT) y Domótica. introduce el concepto de eventos y acciones, lo que permite trabajar con una estructura de control muy clara. A diferencia de los lenguajes de programación tradicionales (ejecución secuencial), Smart Home es un lenguaje basado en eventos, con un ejecución reactiva (el programa espera a que algo pase).  El compilador a construir recibe un archivo de texto (script) conteniendo detección de eventos condicionales o iterativos y acciones a realizar cuando se cumplen las mismas y deberá indicar si está bien construido (adecuado al formato indicado, sin errores) de otra manera indicar los errores; adicionalmente a medida que analiza el script deberá transformar el contenido en un documento HTML.    Hay dos grupos de herramientas que se pueden usar para generar los analizadores: El analizador lexicográﬁco es un módulo que recibe una secuencia de caracteres que componen el documento a analizar y lo convierte lógicamente en una secuencia de tokens. El analizador sintáctico recibe la secuencia de tokens que le entrega el analizador lexicográﬁco y veriﬁca si es correcta de acuerdo a una determinada gramática. Adicionalmente puede generar diversas salidas de acuerdo a criterios especiﬁcados.  1) Se utilizan expresiones regulares y autómatas ﬁnitos para el análisis lexicográﬁco y la técnica LALR para el análisis sintáctico. Ejemplos de esto son lex y yacc, que generan código C o C++, o JLex y CUP, que generan código Java. ﬂex y bison son implementaciones libres y gratuitas de lex y yacc. 2) El otro utiliza la técnica LL(k) tanto para el análisis léxico como para el sintáctico, generando parsers descendentes recursivos. Ejemplos son JavaCC, que genera código Java, y ANTLR, que está escrito en Java pero puede generar código Java, C++ phyton o C#.  https://en.wikipedia.org/wiki/Comparison_of_parser_generators 2. Características de lenguaje SMART HOME   Introducción Smart Home es un lenguaje de programación orientado a eventos que controla una casa inteligente.  Su función es reconocer, validar y transformar instrucciones de texto sencillas ("Si la temperatura sube, enciende el aire") en una interfaz web funcional o en un sistema lógico de control. El usuario escribe reglas de automatización en un archivo de texto. El intérprete procesa ese texto y genera un Dashboard HTML/JS donde se puede ver el estado de los dispositivos.  Componentes léxicos o tokens Palabras Reservadas: Son términos fijos que definen la estructura de control del lenguaje. No pueden usarse como nombres de dispositivos.  ● WHEN : Inicia un bloque disparado por evento. ● IF / THEN / ELSE : Estructuras condicionales. ● DO : Delimitador de inicio de acción. ● END : Finalización o cierre de bloque de acción  ● EVERY : Define una tarea programada por tiempo. Observaciones   # No se distinguirá entre mayúsculas ni minúsculas.   # Las palabras reservadas no se podrán utilizar como identiﬁcadores. Identificadores de Sensores, Dispositivos y Atributos  Representan los objetos físicos y sus propiedades. ● Sensores (Dispositivos de Entrada) : Son dispositivos de "solo lectura" que proporcionan los datos para las condiciones de los bloques `WHEN` e `IF`.  sensor_temp   Temperatura °C -10.0 a 50.0 Temperatura dentro de la casa.  sensor_humedad  Humedad % 0% a 100%  Nivel de humedad ambiental.  sensor_luz   Iluminancia lux   0 a 1000  Nivel de luz.  sensor_movimiento Presencia BOOL  TRUE/FALSE   Detecta si hay alguien en la sala. sensor_humo   Seguridad          BOOL   TRUE/FALSE  Detector de incendios. A utilizarse entre comillas. ● Booleanos: `TRUE`, `FALSE` en sensores, `ON`, `OFF` en dispositivos ● Numéricos con Unidad: El lexer debe identificar el número y además la unidad de medida. ◦ TEMPERATURA: expresada en grados centígrados Ej. `25°C`, `-5°C`. ◦ PORCENTAJE: acompañados del símbolo % Ej. `50%`, `100%`. ◦ TIEMPO: segundos, minutos, u horas Ej. `10s`, `5m`, `1h`. ◦ ILUMINANCIA: Ej. 600lux   0 a 1000  ● HORA: Ej. `06:00`, `23:15` (debe respetar el formato `HH:MM` de 24 horas). ● FECHA: Ej: 21/04/2026  (debe respetar el formato DD/MM/AAAA) ◦ A los efectos de este práctico limitaremos las fechas de la siguiente manera ● Año debe ser un número entre 1900 y 2099. ● Mes debe ser un número entre 1 y 12 ● Día debe ser un número entre 1 y 31 ▪ No es necesario validar correspondencia entre día y mes (ej. 31 de feb). ● Email  Operadores y Delimitadores  ● Comparación: `==` (igualdad), `!=` (diferente), `>`, `<`, `>=`, `<=`. ● Lógicos: `AND`, `OR`, `NOT`. ● Asignación: El signo `=` para cambiar estados (ej. `brillo = 50%`). ● Puntuación: El punto `.` para acceder a atributos  E-mail Un correo electrónico es una secuencia de caracteres que describe el patrón de un correo electrónico válido.
